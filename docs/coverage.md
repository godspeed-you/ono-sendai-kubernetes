# Coverage

What of [the specification](architecture/kubernetes-provider.md) is built, section by section, with the
evidence for each verdict. Written to be argued with: every row names a module, a test, or the
thing that is missing.

This is not [`STATE.md`](STATE.md). The board says what the last session did and what the next one
should do. This document says where the whole surface stands, including the parts nobody has
started, and it is the only place the untouched sections are counted.

Read as a **snapshot taken on 2026-09-06**, against `implementation` at `ad03456`, re-derived from
the tree rather than from the previous snapshot. The previous reading was taken earlier the same
day and five commits ago, and the thing it measured most carefully — how much finished work no
user can reach — is the thing that moved furthest. Every row below was checked by opening the code
the citation leads to; the reachability boundary was checked by reading
`grep -rn "ono_provider_kubernetes::" crates/ono-kubernetes-plugin/src/` rather than by assuming.
A coverage map that does not date itself is the second way to be dishonest about state.

---

## The headline

Of the **70 numbered sections**, 13 are implemented, 53 are partial, **none is built-and-unreachable
and none is without code**, and 4 are advisory with nothing to implement. Of the **7 appendices**,
6 are partial and 1 is advisory. Of the **22 core invariants of §4**, 21 hold, 1 holds partly, none
holds only in the library, none is vacuous and **none fails**.

The number that moved is the reachability ratio, and it moved almost all the way.
**`ono-kubernetes-plugin` imports twenty-two of the twenty-four domain modules**, up from thirteen.
The "domain only" column went from twelve sections to **zero**: the watch is opened and answers
while it is still watching, the session is held across invocations, and Events, logs, evidence,
temporal, causal, condition, plan and mutation each have a word a user can type. Eight of the
fourteen invariants that held only inside the library, or only partly, now hold end to end.

The two modules no user can reach are **`live` and `budget` — 1,474 lines with 40 tests**. That is
what is left of what was, a day ago, 10,356 lines and 239 tests.

The package contributes **30 targets and 2 commands**, and still zero verbs of its own.

642 tests across the workspace — 498 in the domain crate and 144 in the package — all green, no
live cluster and no network.

Two claims that were made a day ago and are withdrawn here, in the direction that costs something:

- **Gate J is no longer "not satisfiable as worded".** `ADR-0586 (core)` gave a package a
  concurrency ceiling and a worker per invocation, so the gate's word is now reachable. This
  provider does not reach it: it pins core at `879d390`, which predates that change, and holds its
  sessions in `Rc<RefCell<…>>`, which the new SDK's `Send + Sync` handler bound refuses. The gate
  moved from a finding about core to work owed here.
- **K2's spatial requirement is no longer blocked on core either.** `ADR-0584 (core)` makes a
  contributed target a kind of place and `ADR-0585 (core)` runs a contributed relation between two
  of them. The door is open and this package walks through none of it.

## How a section was classified

| Class | Means |
|---|---|
| **implemented** | The requirements are met and tests pin them. |
| **partial** | Some requirements met; the row names the ones that are not. |
| **domain only** | Built and tested in `ono-provider-kubernetes`, with nothing in `ono-kubernetes-plugin` routing it to a user. Where such a section is *also* incomplete in the library, the row says so — the class is decided by reachability first, because an unreachable capability is not a capability. **No section is in this class today**, and the class is kept because it is the distinction this document exists to make. |
| **not started** | No code. |
| **advisory** | Thesis, open questions or informative notes: there is no requirement to implement. Named as its own class rather than filed under "not started", because a section nobody was asked to build is not a gap. |

A `MAY` nobody took is noted as such and is not counted against the section. A doc comment citing
a section number was treated as a pointer, never as proof.

## The 22 core invariants of §4

These are the promises the product makes. Twenty-one hold, one holds partly, none holds only
inside the library, none is vacuous and none fails.

| # | Invariant | Status | Evidence |
|---|---|---|---|
| 1 | The API server is the authority | holds | No local store and no synthesis. The session that now exists caches what a cluster *is* — its discovery documents and its published schemas — and what it holds only under a watch that is synchronised; every such answer says `origin=cache` rather than passing for a read. |
| 2 | Discovery is authoritative for what is served | holds | `Gvr::path()` builds every REST path from the discovered resource; no endpoint is compiled in, including the watch collection and the mutation target. `should_refuse_a_mutation_the_cluster_does_not_offer_on_that_resource`. |
| 3 | Native Kubernetes identity remains inspectable | holds | `api_group`, `api_version`, `kind`, `resource_name` and `scope` on every dynamic record; `target_kind` on every edge; `api_version` and `kind` on every event, condition, timeline and finding record. |
| 4 | `metadata.uid` is the canonical lifetime identity | holds | All 31 contributed schemas declare an identity and every one of them names `uid` as a component; `k8s-change` adds `segment` beside it, so an object re-listed after a break cannot collapse onto the observation made before it. |
| 5 | A name is not a lifetime identity | holds | `Locator` is a separate type from `Identity`; `should_not_attach_an_event_to_a_later_lifetime_of_the_same_name` and the UID precondition on every delete are the two boundary proofs. |
| 6 | `resourceVersion` is a continuity token, not a clock | holds | `ResourceVersion` derives no ordering, so the comparison does not compile ([ADR-0006](adr/ADR-0006-resource-version-carries-no-ordering-so-the-forbidden-comparison-does-not-compile.md)), and no schema declares a time read off another machine's clock as a `timestamp` a shell could sort. |
| 7 | `generation` and `resourceVersion` are not conflated | holds | Both are separate fields, and `reconciliation.verified_convergence` is a key of its own so a matching `observedGeneration` cannot read as health. |
| 8 | Desired and observed state stay distinguishable | holds | Structural on `k8s-resource` (`spec` and `status` are separate maps from `Intent`), by field documentation on the 19 curated schemas, and by `stage` on a mutation answer, which is null for a dry run because nothing was written. |
| 9 | Conditions are structured observations, not one string | holds | Was *holds partly*. `get k8s-condition` answers one record per condition with `condition_type`, the verbatim `status`, `reason`, `message` and `last_transition_time` beside its `clock` — the three fields that used to reach nobody. | 10 | Owner references beat label-name heuristics | holds | `should_say_an_owner_reference_names_the_controller_where_it_does` and `should_derive_a_service_s_selection_from_labels_and_say_that_it_derived_it` run end to end, and the second one's record says `asserted: false` where the first says `true`. |

## The largest gaps, in the order they block each other

Five entries are kept struck through. A gap list that quietly loses its top entries teaches a
reader nothing about what moved, and four of these five closed in one day.

**1. ~~A contributed target is invoked with no options.~~ Closed in core.** It was read as the
largest gap and it was, until `provider.query` carried the invocation's words through the same
parser the command route already used.

**2. ~~There is no session.~~ ~~Written, tested, and not wired.~~ Wired.** `sessions::Sessions`
lives in the package process for as long as the process does, keyed on the provider instance, the
resolved endpoint and the transport posture — a key that may only ever *split* two invocations
that would have shared a session, never merge two that would not
([ADR-0021](adr/ADR-0021-a-session-lives-in-the-process-and-is-keyed-on-what-the-operator-configured-never-on-what-the-cluster-said.md)).
§50.2 is measured rather than argued, §12.4 has a reader, §10.4 has a caller and §20.2 has two
origins. It is not `state.persist`, and the ADR says why: a snapshot restored from disk arrives
with no evidence that it is still about the same cluster.

**3. ~~The watch cannot be opened.~~ ~~It can now, and nothing opens it.~~ Opened, and live.**
`k8s-change` lists, watches from that listing's version, and emits a record as each frame arrives
with the body still open. The thing that made it possible was not in core: `broker::Lease` owns
`&mut Ctx` for the length of one handler and lends it out one caller at a time, so a brokered
connection borrows the invocation for one *read* rather than for the life of the connection
([ADR-0023](adr/ADR-0023-a-brokered-connection-borrows-the-invocation-for-one-read-so-a-watch-can-answer-while-it-is-still-watching.md)).
`ADR-0022` §5 had recorded the limitation as a finding about the SDK; the first of its three
shapes turned out to need no change in core at all, and that finding is withdrawn.

**4. ~~No relationship, place or role reaches a user.~~ Closed for relationships and roles.** The
spatial half is gap 2 below, and its reason has changed.

**5. ~~Nothing is exported for a cross-system resolver.~~ ~~Built, and reaching nobody.~~
Routed.** `get k8s-evidence` is §47.7's `MUST`, which was the sharpest unmet sentence in the
specification a day ago.

The gaps that are now largest, in the order they block each other:

**1. This provider does not answer two invocations at once, and Gate J now says that is its own
fault.** `ADR-0586 (core)` gave a package a worker per invocation and a declared ceiling —
`Plugin::concurrent_invocations(n)` in code, `runtime.max_concurrent_invocations` in the manifest,
the smaller of the two winning, and `runtime.concurrency_limit` rather than a quarantine beyond
it. That ADR names this provider's Gate J as one of the two pieces of work that found the bug. It
is not reached here for three independent reasons, each checkable: `Cargo.lock` pins core at
`879d390`, which predates the change; `sessions::Sessions` is an `Rc<RefCell<…>>` and the new
SDK's handler bound is `Fn(&mut Ctx) -> Outcome + Send + Sync`; and neither the manifest nor
`plugin()` declares a ceiling. `tests/isolation.rs` still queries two contexts sequentially and its
header still says the SDK serves one request at a time, which is true of the revision this
repository builds against and no longer true of core. **This blocks K0's claim** and nothing else.

**2. ~~Nothing is a place.~~ Closed but for `up` and `map`.** A Kubernetes object *is* somewhere
now. Every schema this package declares a target for is a kind of place (`ADR-0584 (core)`, which
needed no line here), `package/manifest.yaml` declares thirty-three `contributions.relations`
shapes between them, and a command answering for the shell's own `spatial-relation` target asserts
the edges under a `relation.write` grant that is never given by default. **`enter`, `near` and
`follow` reach a cluster**, proved over the real `ono` binary in
`crates/ono-kubernetes-plugin/tests/spatial_shell.rs`, and **Gate A's five verbs are all
reachable** — "entered" included, for a CRD invented after this package was built. ADR-0027
records the decision and what it cost: the shell re-reads a place with an invocation carrying no
arguments at all, so an invocation that names no cluster now stands where the operator's last one
stood, and falls back to the kubeconfig's `current-context` behind that (§7.1). Two of §69's
eleven verbs still do not reach Kubernetes. **`up`** cannot: landing on a parent needs the
plugin-defined aggregate space of §36.4 and `docs/contracts/kuang/contributions.v1.yaml` gives a
package no way to declare one, so it refuses with `spatial.no_parent` naming exactly that — the
spatial parent is reachable instead as a `…_to_namespace` relation, kept distinct from ownership
because §35.6 is explicit that it is (`…_to_replicaset` is the other shape). **`map`** was not
exercised and is not claimed.

**3. There is a live stream and no live view.** §41.1's `MUST` is to use the inherited live-view
contract; the package opens no host view, `live.rs` has no importer, and `stale` — the one of
§41.4's six states that belongs to a view rather than to a stream — reaches nobody. This is K3's
one unmet requirement, and K3's other five are met and routed.

**4. Nothing sends a `SelfSubjectAccessReview`.** `plan::Preflight` has the slot and
`should_not_report_permission_as_granted_when_no_preflight_ran` keeps it honest rather than filling
it. It is K4's one unmet requirement, §46.2's missing plan content, §21.2 and §21.3, and the
`AUTHORIZATION` line Appendix E spells and this package cannot produce.

**5. No synthetic external resolver exists.** K5's fifth requirement and §60.8 step 3. The
evidence half is done and routed; what is missing is a second, unrelated package that maps it, and
the point of the test is that writing one requires no change here.

**6. §34.2's failure isolation, which is three rows at once.** One broken aggregated APIService
takes down an unqualified `--kind` search. It is also §48.6 and Appendix D.3, it is one of the two
sections above with no test, and it has no fixture. Deliberate, recorded, and still the last
invariant of §4 that is not whole.

**7. Two domain modules cannot be asked for.** `live` and `budget` — 1,474 lines, 40 tests, zero
importers. `live.rs` is gap 3; `budget.rs` is §49.5's throttling and §49.2's `Retry-After`, and
nothing retries anything anywhere.

**8. Nothing detects a discovery change while a session is live.** `Session::crd_updated` and
`group_version_changed` are correct and have no runtime caller, so a CRD installed mid-session is
invisible until a fingerprint disagreement or a new process. It is §11.4's other half, §33.2,
§50.2's "incrementally refreshed", and steps 3 and 4 of §60.1.

**9. Four relationship words the vocabulary names and nothing emits.** `bound-to` is the worst of
them, because a query may narrow to it and will always come back empty (§30.2). The others are
`has-address` (§27), `binds`/`grants-to` (§32.2) and a NetworkPolicy edge (§31), and none of the
four is reachable by any spelling.

**10. There is no compatibility matrix and no version axis in CI.** §5.1's `MUST`, §5.5 and Gate N,
in one absence. [`README.md`](../README.md) now states the five support axes §15.5 requires, which
discharges that `MUST` and not this one: an axis table is a claim about *shape*, and a matrix is a
claim about *versions*, which only a CI run against two of them can support.

**11. No audit record is emitted.** §51.6 and §27.6 of the generic contract. The reason is worth
keeping precisely: the host call exists and needs no capability, and the supervisor stores what it
receives where no test can read it — so under "no test, no code" the emission was not written, and
the fix is an accessor in core rather than a line here.
